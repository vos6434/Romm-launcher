Steam Deck Raw Artifact Test Guide
=================================

Purpose
-------
Use this guide to run the raw Linux artifact (tauri-app) on Steam Deck.
This helps isolate whether AppImage packaging is causing the white-screen issue.

Prerequisites
-------------
- Steam Deck in Desktop Mode.
- You downloaded artifact: steamdeck-raw-binary-main-<COMMIT_SHA>.zip
- Artifact contains: tauri-app-<COMMIT_SHA>.tar.gz

1) Download and extract artifacts
---------------------------------
In Desktop Mode, place files in a dedicated folder, for example:
  ~/Downloads/romm-raw-test/

Inside that folder, you should have:
  - tauri-app-<COMMIT_SHA>.tar.gz

Extract it:
  tar -xzf tauri-app-<COMMIT_SHA>.tar.gz

After extraction, confirm files exist:
  ls -la
Expected:
  - tauri-app
  - build-info.txt

2) Verify you are testing the expected commit
---------------------------------------------
Open build-info.txt:
  cat build-info.txt

Check these fields:
  - commit_sha=<COMMIT_SHA>
  - run_id=<...>
  - built_at_utc=<...>

If commit_sha is not the one you intended to test, stop and download the correct artifact.

3) Make binary executable
-------------------------
  chmod +x ./tauri-app

4) Run raw binary with SteamOS-safe env flags
----------------------------------------------
Run from the same folder:

  GDK_BACKEND=x11 \
  WAYLAND_DISPLAY= \
  WEBKIT_DISABLE_DMABUF_RENDERER=1 \
  WEBKIT_DISABLE_COMPOSITING_MODE=1 \
  GSK_RENDERER=cairo \
  ./tauri-app

5) Capture terminal output for diagnosis
----------------------------------------
If needed, collect startup output to a log file:

  GDK_BACKEND=x11 \
  WAYLAND_DISPLAY= \
  WEBKIT_DISABLE_DMABUF_RENDERER=1 \
  WEBKIT_DISABLE_COMPOSITING_MODE=1 \
  GSK_RENDERER=cairo \
  ./tauri-app 2>&1 | tee raw-run-log.txt

Share raw-run-log.txt if troubleshooting is needed.

6) Interpret results
--------------------
- If raw binary renders correctly but AppImage is white:
  AppImage packaging/runtime is the likely root cause.

- If raw binary is also white:
  Issue is likely WebKit/EGL runtime compatibility beyond AppImage packaging.

- If raw binary fails with:
  "error while loading shared libraries: libwebkit2gtk-4.1.so.0: cannot open shared object file"
  this means SteamOS host does not provide WebKitGTK 4.1 runtime libs for standalone execution.
  In this case, run the extracted AppDir binary with bundled libs (next section).

6b) Run extracted AppDir binary with bundled libs
-------------------------------------------------
This bypasses AppImage runtime wrapper while still using bundled GTK/WebKit libs.

From the folder containing the AppImage:

  chmod +x "RomM Launcher_0.1.0_amd64.AppImage"
  APPIMAGE_EXTRACT_AND_RUN=1 "RomM Launcher_0.1.0_amd64.AppImage" --appimage-extract

Run the inner binary with explicit library path:

  APPDIR="$PWD/squashfs-root"
  WEBKIT_EXEC_PATH="$APPDIR/usr/lib/x86_64-linux-gnu/webkit2gtk-4.1"

  LD_LIBRARY_PATH="$APPDIR/usr/lib:$APPDIR/usr/lib/x86_64-linux-gnu" \
  WEBKIT_EXEC_PATH="$WEBKIT_EXEC_PATH" \
  GDK_BACKEND=x11 \
  WAYLAND_DISPLAY= \
  WEBKIT_DISABLE_DMABUF_RENDERER=1 \
  WEBKIT_DISABLE_COMPOSITING_MODE=1 \
  GSK_RENDERER=cairo \
  "$APPDIR/usr/bin/tauri-app"

If that folder does not exist, try this alternate WebKit process path:

  WEBKIT_EXEC_PATH="$APPDIR/usr/libexec/webkit2gtk-4.1"

Note: messages like "failed to load module canberra-gtk-module" are common on SteamOS
and are usually non-fatal for this test.

Interpretation:
- If this works but running AppImage directly is white:
  AppImage runtime wrapper/integration is the failing layer.
- If this still fails with EGL errors:
  bundled WebKit/EGL path itself is incompatible on SteamOS.

7) Optional convenience launcher script
---------------------------------------
Create a helper script run-raw.sh:

  cat > run-raw.sh << 'EOF'
  #!/usr/bin/env bash
  set -e
  GDK_BACKEND=x11 \
  WAYLAND_DISPLAY= \
  WEBKIT_DISABLE_DMABUF_RENDERER=1 \
  WEBKIT_DISABLE_COMPOSITING_MODE=1 \
  GSK_RENDERER=cairo \
  ./tauri-app
  EOF
  chmod +x run-raw.sh
  ./run-raw.sh

8) Common mistakes
------------------
- Running an old artifact folder by accident.
- Forgetting chmod +x on tauri-app.
- Running from the wrong directory (where tauri-app is not present).
- Skipping commit_sha check in build-info.txt.
